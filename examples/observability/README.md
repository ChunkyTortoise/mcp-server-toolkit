# Observability Demo

Real OTel spans flowing into Jaeger — both as a local Docker stack and as a
public Render deployment that stays warm via a 15-minute trace seeder.

## What you see

Each span carries production-grade attributes that hiring managers care about:

| Attribute | Source |
|---|---|
| `workflow.name` | Top-level span (e.g. `agentic_rag.query`) |
| `workflow.cache_hit` | TTL cache lookup result |
| `llm.provider` / `llm.model` | Routed model |
| `llm.input_tokens` / `llm.output_tokens` | Real token counts from the SDK Usage object |
| `llm.cost_usd` | Computed via `CostTracker` against `mcp_toolkit/pricing/2026.json` |
| `tool.name` / `tool.duration_ms` | Per-tool child spans |
| `tool.cost_usd_partial` | Cost attribution down to individual tool calls |

Everything is generated by the same code path used by the framework — the seeder
calls `TelemetryProvider.span()` and `CostTracker.record_usage()`, the same APIs
production tools use.

## Local — Docker Compose

```bash
docker compose up -d                                   # start Jaeger
pip install 'mcp-server-toolkit[telemetry]'
OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318 \
    python demo.py                                     # 3 sample spans
OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318 \
    python seed_traces.py                              # 8-14 realistic workflows
open http://localhost:16686                            # browse traces
```

## Public — Render blueprint

`render.yaml` provisions two services:

1. **`mcp-toolkit-jaeger`** — Jaeger all-in-one, public UI on free tier
2. **`mcp-toolkit-trace-seeder`** — cron firing `seed_traces.py` every 15 min
   over Render's private network so the dashboard is never empty

Deploy:

```bash
# 1. Push this repo to GitHub
# 2. Open https://dashboard.render.com/blueprints/new
# 3. Connect the repo and select examples/observability/render.yaml
# 4. Render provisions both services in ~3 min
```

After deploy:

- Public UI: `https://mcp-toolkit-jaeger.onrender.com`
- Cron logs: Render dashboard → mcp-toolkit-trace-seeder → Logs
- Internal OTLP ingest: `http://mcp-toolkit-jaeger:4318` (cron only)

## Why this matters

Most MCP demo repos show *that* OTel is wired up. This one shows *what*
production traces look like — cost attribution, cache hit/miss patterns,
multi-tool workflows, and per-call token accounting — in a live URL a hiring
manager can click without installing anything.
